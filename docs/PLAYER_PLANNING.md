# 유저 시점 기획 세션 안내서

작성일: 2026-10-22 · 대상: 새 「유저 시점 기획」 세션
게임을 **직접 해 보는 유저의 눈으로** 보고 개선점과 새 기획을 내는 세션을 위한 문서.
같이 읽을 문서는 다음과 같다.
- `docs/CONTENT_PLANNING.md`: 기획서 형식·기획 원칙
- `docs/GAME_DESIGN.md`: 세계관
- `docs/content/*.md`: 이미 확정된 기획서
- 프로젝트 문서 `claude/BACKLOG.md`, `claude/CONTENT_RETIRE.md`

---

## 0. 이 세션의 역할

- **유저처럼 플레이하고 느낀 점에서 출발해 기획한다.** 구현은 하지 않는다. 구현은 다른 세션이 맡는다.
- 순서는 다음과 같다.
  1. 유저 유형을 하나 골라 그 사람이 되어 플레이하거나 저장 데이터를 꾸며 그 구간을 본다.
  2. 「유저 리뷰 노트」에 불편한 점, 지루한 점, 그만두고 싶어지는 지점, 좋았던 점을 적는다.
  3. 대표님께 문제와 개선안 2~3개를 보여 드린다. 선택지에는 번호를 붙이고 추천안을 표시한다.
  4. 고른 안을 `CONTENT_PLANNING.md` 4장 형식의 기획서로 남긴다.
- 숫자나 재미를 「느낌」으로만 말하지 않는다. 직접 해 본 화면, 걸린 시간, 시뮬레이터 결과를 같이 적는다.

## 2. 유저 여정 (구간별로 보면 좋은 곳)

| 구간 | 대략 위치 | 유저 시점에서 볼 것 |
|---|---|---|
| 첫 10분 | 새 게임 ~ 영지 3 | 무엇을 해야 하는지 바로 아는지, 첫 대사 길이, 첫 보상의 기분, 버튼이 너무 많지 않은지 |
| 첫날 | 영지 3 ~ 15 | 마을·밭·요리·동료가 언제 어떤 순서로 열리는지, 처음 막히는 보스와 그때 무엇을 하라고 알려 주는지 |
| 첫 주 | 영지 15 ~ 30 | 도전·은퇴가 열리는 영지 20 전후, 첫 은퇴를 할 이유와 두려움, 매일 들어올 이유 |
| 중반 | 영지 30 ~ 50 | 성장 속도가 느려지는 곳, 장비 상자·광석·이삭 중 무엇이 모자라는지, 과금 압박 느낌 |
| 끝 | 왕도 51 ~ 60, 엔딩, 61 | 발타사르 난이도, 엔딩 뒤 할 것(탑·은퇴 반복)이 충분한지 |
| 반복 | 은퇴 여러 번 | 같은 구간 반복의 지루함(은퇴 일기·지름길이 풀 예정), 랭킹 동기 |
| 복귀 | 며칠 쉬고 들어옴 | 방치 보상·우편·출석이 반갑게 느껴지는지, 알림 창이 한꺼번에 쏟아지지 않는지 |

## 3. 유저 유형 (돌아가며 하나씩 연기)

1. **처음 온 사람**: 방치형을 잘 모름. 설명을 안 읽음. 화면 폭 360.
2. **출퇴근 방치러**: 하루 3번, 5분씩. 방치 보상·할 일·출석만 챙김.
3. **무과금 완주러**: 광고는 보지만 결제는 안 함. 엔딩까지 얼마나 걸리는지 궁금함.
4. **랭커**: 시즌 1등, 탑 최고 층, 은퇴 효율을 계산함.
5. **수집러**: 동료·테두리·배지 모으기가 목적. 도감·진행률을 찾음.

## 4. 직접 해 보는 방법 (이 저장소에서)

- 웹 게임 띄우기: `python3 -m http.server 8765`(백그라운드) 후 Playwright(Chromium 설치됨)로 `http://localhost:8765/` 열기
  - 폰 폭 320·360·390·430으로 화면을 찍어 보기
- 저장 데이터는 localStorage 키 **`acorn-idle-v1`**(JSON, 전역 `S`)
  - 원하는 구간을 보려면 값을 꾸며 넣고 새로고침한다. 예: `best`·`stage`·`gold`·`memory`
- `?demo=goblin`: 황금 고블린 미리보기(저장 안 됨)
- 시간·밸런스 시뮬레이터
  - `tools/balance_sim.py`: 전체 성장 곡선
  - `tools/capital_sim.py`: 왕도
  - `tools/challenge_sim.py`: 탑·던전
  - JS 판은 `tools/sim/`
- 대표님이 보시는 미리보기 페이지(Artifact)가 따로 있다. 실제 게임과 같은 코드이고, 파일 한도 때문에 `tools/build_preview.py`로 만든 사본이다.
- 앱 화면은 이 환경에서 실행할 수 없다(Flutter는 CI에서만 컴파일됨). 화면 흐름은 웹과 같다고 보고 웹으로 확인한다.

## 6. 이미 정해졌거나 진행 중인 것 (겹치지 않게)

- 은퇴 심화 「카엘의 은퇴 일기」: 확정, 구현 대기(`claude/CONTENT_RETIRE.md`, 그림 `claude/ART_RETIRE.md`)
- 도전 미정: 탑 주간 랭킹, 100층 이후 보상, 동료 카드 던전
- 출시 후 검토: 내 사진을 다른 영주에게도 보이기
- 아직 기획 안 한 큰 주제(`CONTENT_PLANNING.md` 2장): 2부 지역 확장, 동료 관계·이야기, 정기 이벤트, 마을 확장, 상점·패스 설계
  - 유저 리뷰에서 근거가 나오면 이 중 무엇을 먼저 할지 같이 추천한다.

## 7. 지켜야 할 규칙

- 대표님과의 대화는 **한국어, 쉬운 말, 결과 먼저**.
- 기획 원칙은 `CONTENT_PLANNING.md` 3장을 따른다(톤, 직업 4자리 고정, 확률 공개, 강제 광고 없음, 기존 공식 유지, 웹·앱 같은 필드).
- 확정된 기획서는 저장소 `docs/content/`(브랜치 → PR → main 병합)와 프로젝트 문서 `claude/CONTENT_{주제}.md`에 같이 둔다.
- 대표님이 주신 새 항목은 바로 하지 않고 `claude/BACKLOG.md`에 먼저 적는다.
- 보안: 비밀 키·비밀번호를 받거나 코드·문서에 넣지 않는다. 계정 생성·로그인은 대표님이 직접 한다.
